# Campus Events

College event management MVP split into two workspace applications:

- `frontend/`: Next.js, React, TypeScript, and Tailwind UI on port `3000`.
- `backend/`: Express, TypeScript, and Mongoose API on port `5000`.

## Run locally

```bash
npm install
npm run dev
```

The root `dev` command starts both workspaces. To run them separately:

```bash
npm run dev --workspace frontend
npm run dev --workspace backend
```

Copy `backend/.env.example` to `backend/.env` and set `MONGODB_URI`. The backend exposes:

- `GET /api/health`
- `GET|POST /api/events`
- `GET|POST /api/registrations`
- `POST /api/registrations/check-in`
- `GET|POST|PUT|DELETE /api/admin/events` (requires `x-admin-key` or `Authorization: Bearer ...`)
- `GET /api/events` and `GET /api/events/:id` return published, registration-enabled events.
- `GET|POST /api/registrations` and `GET /api/registrations/:id` require the authenticated student session cookie.

Open `/admin` from the student navigation, enter the same `ADMIN_API_KEY`, and manage events from the protected dashboard. The admin page supports event CRUD, detail inspection, search, category/department/status filters, event-wise registration counts, registration enable/disable controls, participant management, and venue QR display. Open an event's **Participants** view to search and filter students, inspect student and registration details, review check-in status, and approve or reject registrations. Open an event's details and choose **Display check-in QR** to show its opaque, server-generated check-in code.

Student routes are available at `/student`, `/student/login`, `/student/signup`, `/student/events`, and `/student/registrations`. Student authentication uses email/password accounts with an HTTP-only session cookie. The student dashboard shows a welcome summary, upcoming events, registration totals, the next registered event, and check-in status. Student registration creation is protected against duplicates, expired deadlines, unpublished events, disabled registration, and capacity limits.

Approved students can open a registration and choose **Scan event QR to check in**. The camera scanner accepts only an event QR generated by an admin. The server verifies the student session, event token, registration, approval, and current check-in state atomically; repeat scans return a duplicate check-in error without changing the original timestamp.

The protected `GET /api/admin/dashboard` endpoint supplies the admin overview statistics, upcoming events, recent registrations, and event registration/check-in chart data. `GET /api/students/me` supplies the authenticated student dashboard profile.

Open http://localhost:3000. Use **Admin portal** in the top navigation to preview the admin dashboard.

## Deploy on Vercel

Deploy `frontend/` as one Vercel project using the Next.js preset. Set `NEXT_PUBLIC_API_URL` to the deployed backend URL.

Deploy `backend/` as a second Vercel project. The included `backend/vercel.json` exposes the Express API through a serverless function. Set `MONGODB_URI`, `MONGODB_DNS_SERVERS`, `FRONTEND_URL`, `ADMIN_API_KEY`, `STUDENT_JWT_SECRET`, `BLOB_READ_WRITE_TOKEN`, and the Firebase Admin variables in the backend project. `BLOB_READ_WRITE_TOKEN` is required for persistent event poster uploads on Vercel.

For local development, keep the existing commands:

```bash
npm run dev --workspace backend
npm run dev --workspace frontend
```
